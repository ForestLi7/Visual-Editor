## 2. 五分钟上手

### 2.1 环境要求

- Node.js **20+**
- npm **9+**
- 现代 Chromium 系浏览器（Chrome / Edge 等）

### 2.2 启动编辑器

在项目根目录执行：

```bash
cd 可视化编辑器
npm install
npm run build:runtime   # 首次启动，或修改过 runtime/core 后必做
npm run dev
```

浏览器打开：**http://localhost:5174**

### 2.3 导入一页 HTML

| 方式 | 操作 |
|------|------|
| 本地文件 | 拖放或选择 `.html` / `.htm` |
| 粘贴 | 填写页面名称 → 粘贴完整源码 →「导入并打开」 |
| 全功能演示 | 点击「打开全功能演示」（内置测试页，覆盖 Flex/Grid、媒体、网络等） |

导入成功后会自动进入**工作台**，中央 iframe 显示真实页面。

### 2.4 改一处并导出

1. 在画布**点选**元素 → 右侧**设计**侧栏改颜色或字号。  
2. 顶栏点击**导出 HTML**，或按 `Ctrl+S`。  
3. 用浏览器单独打开下载的 `.html`，确认与编辑器预览一致。

> **保存导入页的正确方式始终是「导出 HTML」**，而不是变更 Diff 里的「应用选中」（后者面向 monorepo 源码）。

## 3. 操作指南

### 3.1 导入网页

**目标**：把成品 HTML 放进编辑器会话。

1. 在连接页选择「本地文件」或「粘贴 HTML」。  
2. 本地文件仅支持 `.html` / `.htm`；过大（>5 MB）会被拒绝。  
3. 导入成功后进入工作台；若左侧图层树为空，见 §8.2。

**更换页面**：顶栏「更换网页」返回连接页，重新导入（当前会话变更未导出则丢失）。

---

### 3.2 改样式与布局

**目标**：在真实 DOM 上调整视觉，画布即时预览。

1. 点选画布元素，或从左栏**图层树**选中。  
2. 右栏 **设计** Tab：颜色（Token 色板 / 取色器）、间距滑块、字号等。  
3. 需要精确属性时，切换到 **CSS** Tab（与「设计」同一套属性，展示形式不同）。  
4. 容器为 **Flex / Grid** 时，侧栏出现专区块：对齐九宫格、列/行、gap；画布有布局参考线。  
5. `Ctrl+点击` 可多选；多选时部分侧栏操作会批量应用。

撤销：`Ctrl+Z`；重做：`Ctrl+Y` 或 `Ctrl+Shift+Z`。

---

### 3.3 改文字

**目标**：修改可见文案。

| 方式 | 操作 |
|------|------|
| 画布双击 | 进入就地编辑（`contenteditable`） |
| 侧栏 | 文本区域编辑后失焦提交 |
| 指令栏 | 如「文字改成欢迎」 |
| 键盘 | 选中可编辑节点后按 `Enter` |

含复杂子标签的节点可能无法整段改字，请选中纯文本节点或只用画布双击。

---

### 3.4 改媒体与上传 OSS

**目标**：更换图片、音频、视频地址。

1. 选中 `img` / `audio` / `video`。  
2. 右栏**媒体**区修改 `src`、`poster`、`alt` 等。  
3. 可点击上传，经服务端代理到 OSS（需配置 `VE_TOOL_TOKEN`，见 §7）。  
4. 导出 HTML 时会同步媒体 URL（含页面内脚本中的引用替换）。

---

### 3.5 使用指令栏

**目标**：用自然语言快速改样式或文字（规则引擎，非 AI 大模型）。

1. 先选中至少一个元素。  
2. 在底栏指令输入框输入，如「字号加大」「加粗」「文字改成欢迎」。  
3. 点击**执行**，或点击快捷芯片（变大、加粗、主色等）填入后执行。  
4. 无选中时会有提示；解析失败会显示原因。

悬停输入框可查看支持的意图列表（样式 / 文字类）。

---

### 3.6 结构模式重排

**目标**：调整同级 DOM 顺序。

1. 左栏图层树切换到**结构**模式（与「检查」相对）。  
2. 先点选要移动的卡片/区块，再拖动到同级目标位置。  
3. 树与画布顺序联动更新；可撤销。

结构模式提示条会说明：拖动的是当前选中的整块，且仅限同级。

---

### 3.7 导出 HTML（推荐保存方式）

**目标**：得到可独立打开的 HTML 文件。

1. 确认画布预览已是期望效果。  
2. 顶栏 **导出 HTML** 或 `Ctrl+S`。  
3. 浏览器下载 `{页面名}.html`。  
4. 单独打开该文件验证（样式、文字、媒体、指令栏改动均应保留）。

有未导出变更时，顶栏会出现琥珀色提示条，显示 pending 数量。

---

### 3.8 变更 Diff 与写回源码（扩展）

**目标**：把会话变更对照仓库文件，可选写入 monorepo。

1. 存在待应用变更时，顶栏 **变更 Diff** 可用。  
2. 抽屉内并排查看「原始 | 修改后」；可勾选文件。  
3. **导入页**的 Diff 针对虚拟文件 `imports/{会话id}.html`（语义行对比），**不是**把导入页写回磁盘。  
4. **应用选中** 写入 `.visualeditorrc.json` 里 `fileMap` 配置的路径（默认 `demo-app` 下文件）。  
5. 应用成功后**不会**刷新 iframe，避免丢失当前编辑；导入页请继续用 §3.7 导出。

---

### 3.9 切换编辑器主题

**目标**：减轻长时间编辑时的视觉疲劳。

- 顶栏 **浅色 / 深色** 只改变**编辑器外壳**（顶栏、侧栏、底栏）。  
- **导入的预览页**默认不随 Shell 改变配色（避免覆盖页面自有 `[data-theme]`）。  
- 若预览颜色仍被改变：拉取最新代码并**重新导入**该 HTML。

测试页若需联调 Shell 主题同步，在页面 `<html>` 上加 `data-ve-allow-shell-theme="true"`（见 [技术方案](./技术方案.md)）。

---

### 3.10 查看控制台与网络

**目标**：排查页面脚本错误或请求失败。

1. 底栏点击 **控制台** 或 **网络** Tab（可展开列表）。  
2. 控制台同步 iframe 内 `console` 与 Inspector 消息；错误数显示在右下角状态。  
3. 网络 Tab 为只读：fetch / XHR / 资源请求的方法、URL、状态、耗时。

## 4. 界面参考

### 4.1 连接页

| 区域 | 说明 |
|------|------|
| Tab | 本地文件 / 粘贴 HTML |
| 拖放区 | 支持拖入 `.html`；拖入时高亮 |
| 全功能演示 | 一键导入内置测试页 |
| 错误区 | 格式错误、服务端失败时显示 |

### 4.2 工作台

| 区域 | 说明 |
|------|------|
| 顶栏 | 页面名、主题、撤销/重做、变更 Diff、导出 HTML、更换网页 |
| pending 条 | 有未导出变更时出现 |
| 指令栏 | NLP 输入、快捷芯片、执行、反馈文案 |
| 左栏 | 图层树：搜索、检查/结构模式、重新同步 Inspector |
| 中栏 | iframe 预览画布 |
| 右栏 | 设计侧栏：设计/CSS Tab、Flex/Grid、媒体、Props |
| 底栏 | 面包屑、调试区（控制台/网络）、错误角标 |

### 4.3 快捷键

| 按键 | 功能 |
|------|------|
| `Esc` | Diff 打开时关闭抽屉；否则取消选中 |
| `Ctrl+Z` | 撤销 |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 重做 |
| `Ctrl+S` | 导出 HTML |
| `Ctrl+点击` | 多选 |
| `Enter` | 对可编辑节点开始改字 |
| 双击 | 画布就地改字 |

## 5. 在 VS Code 中使用

### 5.1 不用插件（推荐）

完成 §2 启动 `npm run dev` 后，浏览器访问 **http://localhost:5174** 即可，功能完整。

### 5.2 使用 Webview 插件

1. 保持 `npm run dev` 运行。  
2. `Ctrl+Shift+P` → **Extensions: Install from Location** → 选择仓库内 `vscode-extension`。  
3. 重启 VS Code。  
4. `Ctrl+Shift+P` → **Visual Editor: 打开可视化编辑器**。

插件仅嵌入 `5174` 页面，能力与浏览器一致。

## 6. 测试环境部署

### 6.1 部署前提（必读）

| 要求 | 说明 |
|------|------|
| 必须 Node 进程 | 提供 `/api/*` 与 `ve-runtime.js` |
| 禁止仅静态 `dist` | 无导入 API、无 runtime 注入会导致白屏或树空 |
| 子路径一致 | `VE_BASE_PATH` 与 nginx `location` 必须对齐（如 `/visual-editor/`） |

### 6.2 Docker 部署（推荐，CentOS 7 等）

**本机打包**

- 须 **Docker Desktop 已启动**（`docker version` 的 Client 与 Server 均有版本号）。  
- 国内拉镜像超时时：

```powershell
npm run docker:pack:cn
```

- 可访问 Docker Hub 时：

```bash
npm run docker:pack
```

产出：`release/visual-editor-docker.tar`。更短步骤见 [docker 部署到测试环境](./docker部署到测试环境.md)。

**上传到服务器**（与 `deploy/run-on-server.sh` 同级目录）：

```bash
yum install -y docker && systemctl start docker
cd /opt/visual-editor   # 你的目录
sed -i 's/\r$//' run-on-server.sh   # 从 Windows 上传时去 CRLF
chmod +x run-on-server.sh
bash run-on-server.sh
```

**容器反复 `Restarting (139)`**：CentOS 7 老 Docker 的 seccomp 限制。请用最新 `run-on-server.sh`（含 `seccomp=unconfined`），或手动：

```bash
docker rm -f visual-editor
docker run -d --name visual-editor --init --restart unless-stopped \
  --security-opt seccomp=unconfined \
  --ulimit nproc=65535:65535 \
  -p 127.0.0.1:5174:5174 \
  -e VE_BASE_PATH=/visual-editor/ \
  visual-editor:latest
```

**自检**（服务器上）：

```bash
docker ps
curl -s http://127.0.0.1:5174/visual-editor/api/health
```

期望：`{"ok":true}` 或等价 JSON。

### 6.3 nginx 反向代理

在 `http { }` 内（若尚未配置）：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
```

在测试域名 `server { }` 内：

```nginx
location /visual-editor/ {
    proxy_pass http://127.0.0.1:5174/visual-editor/;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;

    client_max_body_size 32m;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}
```

完整示例：`deploy/nginx-node2-docker.conf`。

```bash
nginx -t && systemctl reload nginx
```

访问示例：`https://{你的域名}/visual-editor/`  
外网自检：`curl -s https://{你的域名}/visual-editor/api/health`

### 6.4 裸机部署（Node 20+）

```bash
npm run pack
# 上传 release/visual-editor-release.tar.gz 并解压后
npm ci
VE_BASE_PATH=/visual-editor/ npm run start:prod
```

CentOS 7 若 glibc 不足：使用 `deploy/install-node-el7.sh` 或改走 Docker。

### 6.5 局域网 IP 反代

本机 `npm run dev` 默认监听 `0.0.0.0:5174`。nginx 示例：

```nginx
proxy_pass http://172.16.x.x:5174/visual-editor/;
```

开发环境变量见 `editor/.env.development`（`VE_BASE_PATH`、`VE_PUBLIC_ORIGIN`）。

### 6.6 部署后验收清单

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 健康检查 | `/visual-editor/api/health` 返回 ok |
| 2 | Runtime | `/visual-editor/ve-runtime.js` 状态 200 |
| 3 | 导入 | 全功能演示可进工作台，图层树非空 |
| 4 | 导出 | 导出 HTML 单独打开与预览一致 |

## 8. 故障排除

按现象查找；处理完建议 `npm run build:runtime` 后重启 `npm run dev` 或重建 Docker 镜像。

### 8.1 连接与页面加载

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 页面空白、JS 404 | `VE_BASE_PATH` 与 nginx `location` 不一致 | 对齐路径后重启服务 / 重载 nginx |
| MIME 为 text/html 却加载 `main.tsx` | base 路径错误 | 检查 `editor/.env.development` |
| 403，Remote Address 127.0.0.1:7897 | 系统代理拦截 | 关闭代理或规则 `域名,DIRECT` |

### 8.2 编辑器功能异常

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 左侧 DOM 树为空 | `ve-runtime.js` 未构建或 404 | `npm run build:runtime`；确认 runtime URL 200 |
| 点选 / 改样式无效 | runtime 过期或 postMessage 被拦 | 同上；确认访问域名在白名单内 |
| 指令执行后预览有变、导出无变 | 旧 runtime 导出逻辑 | 重建 runtime 并重新部署镜像 |
| 改字后 Diff 无记录 | 未打开 Diff 或无 pending | 先产生变更，再点「变更 Diff」 |
| 主题切换改了预览页颜色 | 旧导入会话或页面允许同步 | 更新代码后**重新导入** HTML |

### 8.3 部署与环境

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `npm: 未找到` | 未装 Node 20+ | 安装 Node 或使用 Docker |
| Docker 拉取超时 | 无法访问 Hub | `npm run docker:pack:cn` 或配置 registry mirror |
| 容器 Exit 139 | CentOS 7 seccomp | §6.2 `seccomp=unconfined` |
| el7 glibc 报错 | 系统过旧 | Docker 或 `deploy/install-node-el7.sh` |

### 8.4 仍无法解决

1. 浏览器开发者工具 → Network：确认 `ve-runtime.js`、`/api/import/page` 状态码。  
2. 底栏控制台是否有 Inspector 或脚本错误。  
3. 对照 [技术方案 §11 故障模式](./技术方案.md) 与研发排查。

## 9. 术语简表

| 术语 | 含义 |
|------|------|
| Shell | 编辑器外壳 UI（顶栏、侧栏等），非 iframe 内页面 |
| Runtime / Inspector | 注入预览页的 `ve-runtime.js`，负责点选与导出 |
| pending 变更 | 会话内已预览、尚未导出或未写回源码的修改 |
| 导入页 | 经 `/api/import/page` 加载的 HTML 会话 |
| 导出 HTML | 主交付方式，下载含当前 DOM 状态的文件 |
